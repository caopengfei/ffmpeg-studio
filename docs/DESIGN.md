## ffmpeg 依赖与自动安装

ffmpeg **不随包分发**（gyan.dev 的 full_build 单个 exe 就有 212 MB），启动时自动探测。

### 探测顺序（即优先级）

| # | 位置 | 说明 |
|---|---|---|
| 1 | **程序所在目录** | 直接放 `ffmpeg.exe`，或把解压出来的文件夹整个丢进去（会往下找 3 层，所以 `<名字>\bin\ffmpeg.exe` 也认） |
| 2 | 之前指定过的路径 | 配置里记的（`%APPDATA%\FFmpegStudio\config.json`） |
| 3 | 常见安装位置 | `C:\ffmpeg\bin`、`%USERPROFILE%\scoop\shims`、WinGet Links 等 |
| 4 | 系统 `PATH` | |

**同级目录排第一是刻意的**：换机器、换盘符之后不会被一条失效的旧配置卡住。

扫描策略（`scanNearby`）是逐层 BFS，最多 3 层 / 200 个目录，跳过 `.` 开头、`node_modules`、
`$RECYCLE.BIN`、`Windows`、`AppData`。另外有个**快路径**：先只 stat 同级、同级 `bin` 两处，
命中就不扫目录树 —— 绝大多数情况是 O(1)。同目录带 ffprobe 的稳定排在前面。

### 两个硬性要求

不满足就按"没找到"处理，而不是让用户卡在一个用不了的组合上：

- `ffmpeg.exe` 与 `ffprobe.exe` **必须在同一目录**。本应用靠 ffprobe 读时长/分辨率/轨道，
  单个 `ffmpeg.exe` 干不了活。这种情况界面会**单独点破**（"找到了 xxx 但旁边没有 ffprobe"），
  而不是笼统说一句"没找到"
- ffmpeg 必须能正常执行 `-version`

### 自动安装

界面给「**自动下载并安装**」按钮，一次把下载、解压、启用做完：

- **下载**：gyan.dev 官方 `release-essentials.zip`（约 110 MB）。地址会 303 到当前最新版，
  不写死版本号。分块读 + 进度回调限频 200ms；`ResponseHeaderTimeout` 30s；
  另加**看门狗**（`time.AfterFunc` + 每收到数据就 `Reset`，60 秒无数据直接中止），
  兜住"网线拔了/被限速到 0"；下完校验字节数与 `Content-Length` 是否一致
- **解压**：`archive/zip`，只挑出 `ffmpeg.exe` / `ffprobe.exe` 写到 `<程序目录>/bin/`，
  官方包里那些 doc、presets 一概不落地
- **启用**：装完自动重新探测，界面直接进主功能

两个安全/健壮性细节：

- 压缩包里的路径一概不信，只用 `filepath.Base` 取文件名 —— 天然免疫 zip slip
- 下载和解压中断时会**回滚**（删临时文件 + 删已写出的 exe）。
  否则可能留下"有 ffmpeg 没 ffprobe"的半成品，白占 170 MB。
  解压时先写 `.part` 再 rename，避免半个文件被当成可用

网络受限时保留手动路径：引导卡片上的「我要手动装」会展开「下载 → 放到这 → 重新检测」三步。

### 排查工具

`tools/locate-probe/` 是命令行诊断工具（**不参与打包分发**），会逐个列出候选路径和最终选中项：

```bash
go build -o build/bin/locate-probe.exe ./tools/locate-probe
cd build/bin && ./locate-probe.exe     # 必须和 ffmpeg-studio.exe 同目录，否则反映的不是真实情况
```

主程序不依赖它；界面引导卡片里的折叠区已列出同样的路径列表，日常排错够用。

## 七个功能的实现要点

| 功能 | 说明 | 要点 |
|---|---|---|
| **转码** | 换容器、换编码格式 | 容器与编码器的兼容性会提前校验，不合法的组合直接置灰 |
| **压缩体积** | 按质量（CRF）或按目标体积 | 目标体积走两遍编码，按 `目标MB×8192÷时长` 反推码率 |
| **截取片段** | 时间轴上拖选区间 | 快速模式不重编码（秒级），精确模式逐帧定位 |
| **缩放分辨率** | 预设或自定义尺寸 | 保持比例时自动取偶数，避免 h264 因奇数尺寸编码失败 |
| **抽帧截图** | 抽单帧 / 批量抽帧 / 设为封面 | 设为封面时写 `attached_pic` 流，视频不重编码 |
| **转 GIF** | 片段转动图 | 默认两遍法（先生成专属调色板），画质远好于直接转 |
| **加水印** | 多水印叠加，实时预览 | 见下文 |

## 水印是怎么做的

- **实时预览**：水印是叠在 `<video>` 上的网页元素，拖动零延迟；不是用 ffmpeg 逐帧渲染
  （那样每调一次要等 1~2 秒）
- **多水印**：图片与文字可混合叠加，列表顺序即层叠顺序，每项可单独启用/禁用
- **位置 / 大小全部靠拖**：拖水印本体移动位置，拖右下角圆点改大小（见下面的"缩放"坑）
- **坐标只存相对比例**（0~1），导出时换成 ffmpeg 表达式 `overlay=x='w*0.05'`，
  所以改输出分辨率水印位置也不会偏
- **时间控制**：每个水印各自设置自己的显示时间段，互不影响，全部通过时间轴完成：
  - **拖红色播放头的圆点**（或直接点/按住空白处）定位播放位置，按住可以连续拖
  - **拖色条两端手柄**分别调整「开始时间」和「消失时间」，拖中段整体平移。
    **调完会自动定位到该水印可见的时刻**（若播放头本来就在区间内则不动，不打断播放）
  - 没设过时间段的水印显示为**斜纹底的「全程」条**，和已限定的实心色条一眼区分
  - 列表项上有摘要：`全程` / `1.5s – 3.0s` / `8.0s 起`
  - 拖过色条后，选中项面板才会出现精确秒数输入（以及「取消时间限制」）
  - **拖不动时会说明原因**：拖到片头/片尾没有余地、或对「全程」水印拖中段时，
    时间轴上方会用暖色提示，而不是静默无反应

  拖动视频进度时，超出各自时间段的合成水印会实时隐藏；导出时对应 `enable='between(t,起,止)'`。
- 导出时图片水印先 `scale` 定尺寸、`colorchannelmixer` 调透明度再 `overlay`，文字水印用 `drawtext`

预览用的是原片；如果原片浏览器解不了（HEVC 的 mkv 之类），会自动转一份 960px 的 h264 代理副本
缓存在 `%TEMP%`，**导出始终用原始文件**。

## 项目结构

```
ffmpeg-studio/
├── main.go                        入口，注册 /media/ 中间件
├── app.go                         暴露给前端的方法
├── internal/
│   ├── config/                    配置持久化
│   ├── media/
│   │   ├── serve.go               /media/ 路由（Range + 授权白名单）
│   │   ├── locate.go              ffmpeg 定位与版本校验
│   │   ├── install.go             自动下载并安装 ffmpeg
│   │   ├── probe.go               ffprobe 读取媒体信息
│   │   └── proxy.go               预览代理副本生成与缓存
│   ├── task/
│   │   ├── spec.go                统一任务模型 + 参数校验
│   │   ├── args.go                Spec → ffmpeg 命令行（纯函数）
│   │   ├── runner.go              执行、进度解析、取消、清理
│   │   └── manager.go             串行任务管理
│   ├── proc/                      子进程创建（Windows 下隐藏控制台窗口）
│   └── watermark/watermark.go     水印 → filter_complex
├── tools/
│   ├── ui-verify/                 UI 回归验证（playwright + mock 后端）
│   └── locate-probe/              ffmpeg 探测诊断（按需编译）
└── frontend/src/
    ├── components/                文件选择、媒体信息、时间轴、命令预览、进度面板
    └── tabs/                      七个功能页
```

`args.go` 是纯函数（输入 `Spec`，输出参数列表），不碰进程，所以能直接单元测试而不用真跑转码。

```bash
go test ./...                    # 后端全部（含集成测试，会真实调用 ffmpeg）
go test ./... -short             # 跳过需要 ffmpeg 的用例

cd frontend && npm test          # 前端纯函数用例
```

### UI 回归验证（拖拽类交互专用）

拖拽、鼠标坐标这类交互**光看代码很容易判断错**（这个项目踩过三次：色条点一下变短、
缩放手柄不跟鼠标、时间轴拖不动）。所以做一个能真跑的验证环境：

```bash
bash tools/ui-verify/verify.sh
```

它做的事：

1. 构建前端，拷到 `tools/ui-verify/verify-dist`（独立副本，避免 `npm run build` 清掉测试视频）
2. 用 ffmpeg 生成一段测试视频
3. 起静态服务（支持 Range），用 playwright + 已装好的 chromium 打开页面
4. **注入 mock 顶掉 Wails 后端绑定**（`window.go.main.App.*` / `window.runtime.*`），
   这样纯浏览器里就能跑真实组件
5. 跑 `e2e-timeline.mjs`（时间轴拖拽）和 `e2e-install.mjs`（自动安装流程），
   用真实指针事件操作并读 DOM 断言

改 UI 外观时用 `shot-sidebar.mjs` / `shot-gallery.mjs` 截图目检，比在脑子里想象样式效果可靠。

> 注意：侧栏按钮同时包含标题和描述，**accessible name 变了** ——
> 脚本里定位请用 `page.locator('.nav-item', { hasText: '加水印' })`，
> 不要用 `getByRole('button', { name: '加水印' })`（后者匹配不到）。

## 踩过的坑

### ffmpeg 与滤镜

1. **drawtext 必须给字体路径**：这个 ffmpeg 构建没有 fontconfig 配置，不指定 `fontfile` 会让 ffmpeg
   直接崩溃（`0xc0000005` + `Fontconfig error`）。现在会自动探测系统字体补上。
2. **Windows 字体路径的冒号要转义**：写成 `fontfile='C\:/Windows/Fonts/msyh.ttc'`，否则滤镜解析失败。
3. **mkv 不能用 format_name 判断**：ffprobe 报的是 `matroska,webm`，用子串匹配会误判成 webm 可播放，
   实际预览黑屏。现在按文件扩展名判断。
4. **`-c copy` 会静默忽略 `-crf`**：没有任何报错，质量参数完全不生效。生成参数时已排除这种组合。
5. **保持比例要用 `-2` 而不是 `-1`**：h264 的 yuv420p 要求宽高都是偶数。
6. **两遍编码的 passlog 要清理**：路径含反斜杠，不能用 `filepath.Glob` 匹配（反斜杠会被当转义符），
   改用 `os.ReadDir` 按前缀扫。
7. **GUI 程序启动控制台子进程会弹黑框**：`SysProcAttr` 里加 `CREATE_NO_WINDOW`（`internal/proc` 统一封装）。
   另外给 ffmpeg 加 `-nostdin`，GUI 程序没有标准输入。

### 前端交互

8. **文字的渲染宽度 ≠ 字号**：缩放手柄按"字号 + 鼠标位移"算，会让手柄跑得比鼠标快好几倍
   （三个字、字号 36px 时实宽约 108px，拖 20px 宽度实际涨 60px）。
   必须按**元素当前实际渲染宽度**等比换算。已抽成 `watermarkLayout.js` 并写了对照测试。
9. **"拖了没反应"必须给反馈**：功能上"没有可拖的余地"是正确的（撞片头片尾），
   但静默无反应会被当成 bug。凡是边界和无效操作，都要有可见提示。
10. **绑定在父元素上的操作要单独留"抓手"**：播放头红线为了不挡住色条拖拽设了
    `pointer-events: none`，那它自己就拖不了 —— 解法是在红线顶端放一个独立的小圆点专门用来抓。
11. **拖拽时坐标要按"按下瞬间"为基准**：每次 `pointermove` 都基于上一帧结果累加会越拖越快。
12. **`pointermove` 要挂在 window 上**：挂在元素上，鼠标一滑出去就断了。

### 测试环境

13. **`page.mouse` 用的是视口坐标**：元素滚出视口后点不到，必须先 `scrollIntoViewIfNeeded()`，
    否则会得到"拖了没反应"的**假故障**。
14. **静态服务器必须支持 HTTP Range**（所以没用 `python -m http.server`，而是 `serve.py`）：
    不支持 Range 时 Chromium 拿不到分段数据，`<video>` 的 `currentTime` 赋值后纹丝不动，
    表现为"拖播放头没反应"。这个坑骗过我一次 —— 当时 `readyState:4, duration:12`，
    但设了 `currentTime=5` 之后仍是 `0`，一度以为是产品 bug。
15. **Wails 的 runtime 依赖 `EventsOnMultiple`**：mock 里少一个就会让组件 setup 抛错、整页空白。
16. **构建前端必须先于编译后端**：`//go:embed all:frontend/dist` 对着旧产物也能编译成功，
    不报错但界面不会更新，容易误判成"改了没生效"。
